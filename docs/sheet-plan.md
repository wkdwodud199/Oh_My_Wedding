# Google Sheets 연결을 위한 최소 변경안

현재 17개 탭은 그대로 두고, 자동화가 읽고 쓰는 **3개 탭만 추가하는 제안**이다. 이 문서와 헤더 템플릿을 만드는 동안 실제 시트는 변경하지 않았다. 결혼일·계약일·예약 상태도 새로 확정하지 않는다.

## 추가할 탭

| 탭 이름 | 역할 | 1행 헤더 템플릿 | 권장 크기 |
| --- | --- | --- | --- |
| `준비업무` | 두 사람이 확인한 할 일, 조사 대상, 마감과 예약 일시 | [준비업무.tsv](../examples/headers/준비업무.tsv) | 1,001행 권장·상한, 최소 14열 |
| `조사결과` | 업체 조사 요약과 출처 | [조사결과.tsv](../examples/headers/조사결과.tsv) | 5,001행 권장·상한, 최소 7열 |
| `변경기록` | 봇이 수행한 수정 이력 | [변경기록.tsv](../examples/headers/변경기록.tsv) | 5,001행 권장·상한, 최소 5열 |

각 TSV에는 **헤더 한 줄만** 있다. 해당 탭의 A1에 붙여 넣으면 된다. 열 순서는 아래와 동일하게 유지하고, 1행은 고정해 두면 편하다. 데이터 행에 병합 셀을 만들지 않는다. 더 작은 격자도 사용할 수 있지만 기록할 빈 행은 남겨 둔다. 프로그램이 행을 자동으로 늘리지는 않는다.

상한은 헤더를 포함한 **탭의 전체 격자 행수**에 적용된다. 실제 데이터가 적어도 `준비업무`가 1,001행을 넘거나 로그 탭이 5,001행을 넘으면 읽기를 중단한다. 업무 1,000개·로그 탭별 5,000건을 넘길 때는 읽기 범위·보관 방법을 먼저 검토한다.

## 준비업무: 정확히 14개 열

| 열 | 헤더 | 입력 규칙 |
| --- | --- | --- |
| A | 업무ID | 필수. 업무마다 고유한 값. 예: `TASK-001`. 생성 후 바꾸지 않는다. |
| B | 영역 | 필수. 예: 예복, 촬영, 혼주, 포인트. |
| C | 할일 | 필수. 예: 업체 비교, 방문 상담, 촬영 참석. |
| D | 상태 | `미정`, `조사중`, `상담중`, `예약완료`, `계약완료`, `완료`, `보류`, `취소` 중 하나. |
| E | 마감일 | `YYYY-MM-DD` 또는 `YYYY-MM`. 월만 쓰면 **그 달 마지막 날**로 처리한다. 연도 없는 날짜는 쓰지 않는다. |
| F | 담당 | 담당자 표시 또는 `공동`. |
| G | 지역 | 조사에 사용할 지역·범위. 예: 서울 종로구. |
| H | 예산 | 금액과 조건을 함께 기입할 수 있는 텍스트. 예: 100만 원 이하, 추가금 포함. |
| I | 조사여부 | 조사할 행에만 명시적으로 `TRUE`. 기본은 `FALSE`. 체크박스를 쓴다면 기본 TRUE/FALSE 값을 사용한다. |
| J | 업체 | 확인한 업체명·지점. 미정이면 비워 둔다. |
| K | 예약일시 | 시간대가 있는 형식 `YYYY-MM-DDTHH:MM+09:00`. 날짜·시각을 확인한 뒤 입력한다. |
| L | 선행업무 | 먼저 끝나야 할 **한 업무의 ID**. 없으면 빈칸. 여러 ID나 업무 제목을 넣지 않는다. |
| M | 메모 | 견적 조건, 준비물, 확인할 사항 등. |
| N | 수정시각 | 프로그램이 기록하는 수정 시각. 처음에는 비워 둔다. |

`준비업무`의 1행은 다음 순서다.

```text
업무ID | 영역 | 할일 | 상태 | 마감일 | 담당 | 지역 | 예산 | 조사여부 | 업체 | 예약일시 | 선행업무 | 메모 | 수정시각
```

마감일·예약일시는 셀 서식을 **일반 텍스트**로 설정해 위 형식을 보존하는 편이 안전하다. 특히 `YYYY-MM`이 시트의 날짜 자동 변환으로 달라지지 않게 한다. `선행업무`는 존재하는 ID만 쓰며 자기 자신이나 순환 관계를 만들 수 없다.

## 조사와 알림을 구분하는 방법

조사는 `조사여부=TRUE`이면서 상태가 `미정`, `조사중`, `상담중`인 업무만 대상으로 한다. 빈 업체 셀이나 빈 가격 셀만 보고 조사 대상으로 정하지 않는다. `보류`, `예약완료`, `계약완료`, `완료`, `취소`인 **해당 업무의 조사와 알림은 멈춘다**.

따라서 **업체 계약·예약**과 **실제 일정 참석·수행**은 다른 행으로 등록해야 한다. 예약 업무를 끝낸 뒤에도 촬영일 알림을 받고 싶으면 촬영 참석 업무를 활성 상태로 남긴다.

아래는 동작 설명을 위한 가상 예시이며 실제 업체나 날짜가 아니다.

| 업무ID | 할일 | 상태 | 조사여부 | 선행업무 | 마감일·예약일시 |
| --- | --- | --- | --- | --- | --- |
| `EX-BOOK` | 촬영 업체 예약하기 | 예약완료 | FALSE | 빈칸 | 확인된 예약 처리 날짜를 필요할 때 기록 |
| `EX-SHOOT` | 촬영 참석하기 | 미정 | FALSE | `EX-BOOK` | 실제로 확인한 촬영 일시를 입력 |

두 번째 행의 `미정`은 이 업무가 아직 끝나지 않았다는 뜻으로 사용하는 활성 상태다. 예약 사실은 첫 행과 `업체`·`예약일시`·`메모`에 기록한다. 촬영을 마친 뒤 두 번째 행도 `완료`로 바꾼다. “예약 완료니까 촬영 행도 예약완료로 바꾸기”를 하면 촬영 알림도 중단된다.

포인트도 필요한 것부터 수동으로 업무 행을 추가하면 된다. 예를 들어 `영역=포인트`, `할일=계약 후기 작성`, `조사여부=FALSE`로 만들고, 확인된 작성 기한을 `마감일`에 적는다. 현재 포인트 탭의 모든 문장을 자동으로 마감 업무로 바꾸지는 않는다.

## 결과·기록 탭의 헤더

`조사결과`는 7개 열이다. 출처JSON에는 출처 URL과 조회·게시 시점 등 프로그램이 얻은 근거를 저장한다. 출처가 제한한 데이터는 별도 저장 조건을 따른다.

```text
기록ID | 업무ID | 조회일 | 영역 | 지역 | 요약 | 출처JSON
```

`변경기록`은 5개 열이다. 변경JSON에는 처리한 필드와 변경 내용을 기록한다. 이 두 탭은 사람이 내용을 맞춰 채우기보다 프로그램의 출력 공간으로 두는 편이 간단하다.

```text
기록ID | 시각 | 업무ID | 요청자 | 변경JSON
```

## 기존 탭을 자동 변환하지 않는 이유

기존 `업체`·`총비용` 등의 빈칸은 미계약, 입력 대기, 해당 없음 중 어느 의미인지 자동으로 확정할 수 없다. 금액만으로 계약 여부나 잔금 기한을 알아낼 수도 없다. 참고용 `(언니꺼)` 탭의 과거 날짜가 현재 일정에 섞이면 잘못된 조사를 하거나 알림을 보낼 수 있다.

처음에는 두 사람이 실제로 관리할 업무 몇 개를 `준비업무`에 옮기고, 명시적인 상태·조사 여부·날짜를 확인하는 것으로 충분하다. 기존 비용표와 비교표는 계속 그대로 사용한다. 자동화가 필요한 데이터만 추가해 원본 구조를 크게 바꾸지 않는다.
